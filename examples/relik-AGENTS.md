# relik (Koleksi) — project knowledge

Collectibles cataloguing + pricing SaaS (trading cards, comics, games, toys,
memorabilia). Bun + Turborepo monorepo.

**Stack:** Go 1.25 API on Fly.io · Expo / React Native 0.81 / React 19 mobile ·
Vite + React 19 + TanStack website · Supabase (Postgres + pgvector, JWKS auth) ·
S3, OpenAI, eBay pricing, Sentry.

**Layout**
- `apps/api` — Go API (chi, pgx, Postgres+pgvector). Cron scheduler, Expo push,
  AI worker. Deployed to Fly.io (`apps/api/fly/*.toml`).
- `apps/mobile` — Expo / React Native. EAS builds.
- `apps/website` — Vite + React + TanStack Router/Query.
- `packages/types` — Go→TS types generated by **tygo** (`generated/**`).
- `packages/ui` — `@koleksi/ui` design system (Koleksi tokens).

**Commands** (from repo root; Bun 1.3)
- Install: `bun install`
- Lint (JS + design gate): `bun run lint` → `turbo run lint` + `bash scripts/design-conformance.sh`
- Test (JS/TS): `bun run test` · Go: `bun run test:go` (`cd apps/api && make test`)
- Codegen (incl. tygo types): `bun run generate`
- Migrate API DB: `bun run api:migrate` · Deploy API staging: `bun run api:staging:deploy` (Fly)

## Hard rules

These are non-obvious and costly to get wrong. An AI without this file *will*
write insecure migrations, wrong stats queries, or trigger paid builds.

### 1. Never push a `v*` tag unless the user asks for a release *this turn*
`.github/workflows/mobile.yml` triggers a **billed** EAS iOS + Android build on
every pushed `v*` tag — the user pays per build. Pushing to `main` is free
(`api.yml`: Go tests + Fly deploy).

Standard flow: smoke-test in the iOS + Android simulators → commit + push `main`
→ verify CI green → **stop.** Do not `git tag`. Wait for an explicit
"release" / "tag v0.0.x" / "push to testers" instruction before
`git tag` + `git push origin <tag>`. Applies on every machine and every fresh
session.

### 2. Enable RLS on every new `public` table
Supabase's `rls_disabled_in_public` linter flags any `public` table reachable
via PostgREST (`anon`/`authenticated`) — even bookkeeping tables like
`schema_migrations`. In every migration that creates a public table, also add:

```sql
ALTER TABLE <name> ENABLE ROW LEVEL SECURITY;
```

Zero policies is fine: the Go API connects as `postgres` (BYPASSRLS), so backend
queries are unaffected; the goal is default-deny on the PostgREST surface the app
never uses. Enforced by `apps/api/internal/store` regression test
`TestPublicTablesHaveRLSEnabled` (`rls_coverage_test.go`) on every Go CI run —
flag it in review too. Reference migrations: `000055_enable_rls`,
`000064_enable_rls_new_tables`, `000067_enable_rls_schema_migrations`.

### 3. Exclude capture-flow drafts from every aggregate over `items`
The mobile capture flow inserts an `items` row (`name='Untitled Item'`,
`collection_id=NULL`) the instant a photo is picked, so uploads have an id to
bind to; backing out leaves a draft (a daily `draft_cleanup` cron clears drafts
older than 7 days). Every aggregate over `items` (counts, sums, distributions,
recommender context, pricing sweeps) MUST filter:

```sql
WHERE user_id = $1 AND collection_id IS NOT NULL
```

Mirror the surfaces that already do this: `store.GetDashboardStats`,
`GetCardStats`, `GetCollectionDNAParams`, `CountItemsByUser`, `GetItemDeltas`,
`ai.recommender`, `jobs.PriceSweepJob`, `jobs.PriceAlertEvaluatorJob`.
Per-collection (`collection_id = $x`) or per-item (`id = $y`) queries don't need
it — drafts aren't reachable from those scopes.

### 4. LISTEN/NOTIFY needs a session-mode connection, not the pooler
The AI worker (`apps/api/internal/ai/worker.go`) listens on `ai_jobs_channel`
via `pq.NewListener` and requires a dedicated **session-mode** DSN
(`sessionDSN`). Supabase's transaction-mode pooler (Supavisor) silently drops
`LISTEN` registrations — anything using LISTEN/NOTIFY must use the session pool /
direct connection, never the tx pooler.

### 5. Never hand-edit generated types
`packages/types/generated/**` is produced from Go structs by **tygo**. Change
the Go source and run `bun run generate`; never edit the generated TS by hand.

### 6. Design-system conformance gate (mobile UI)
`bash scripts/design-conformance.sh` (part of `bun run lint`, and a CI gate)
fails on raw design values in `packages/ui/src/**` and the Collection/Vault +
Insights screen domains:

- no raw hex / `rgba()` / named colours, no numeric px in style props, no raw
  `fontFamily` — source from Koleksi tokens (`koleksiSpace[n]`, `koleksiDark.*`,
  `koleksiRadius[*]`, `withAlpha(token, opacity)`).
- no `eslint-disable` directives; no ad-hoc glass (use `@koleksi/ui` `Glass` /
  primitives); screen roots must use `<Screen>`.
- no user-facing "AI" / "A.I." copy in the Insights domain.

Genuine exceptions: append `// conformance: justified — <reason>` to the line.
